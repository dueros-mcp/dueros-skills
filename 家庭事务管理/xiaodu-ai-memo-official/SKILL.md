# AI Memo

本 skill 用于在本地管理 AI 备忘录。备忘数据只能保存在固定目录：

```text
memory/ai-memo/
```

辅助脚本路径：

```text
scripts/memo_store.py
```

## 核心数据结构

备忘数据保存在 `memos.json` 中，顶层 key 使用 ISO 时间戳。结构如下：

```json
{
  "2026-04-28T10:30:12.345+08:00": {
    "id": "2026-04-28T10:30:12.345+08:00",
    "createdAt": "2026-04-28T10:30:12.345+08:00",
    "updatedAt": "2026-04-28T10:30:12.345+08:00",
    "type": "text_image",
    "query": "用户原始请求",
    "content": "真正要记住的内容",
    "imagePaths": [],
    "imageDescription": "保存时生成的图片描述",
    "tags": [],
    "reminder": {
      "needed": false,
      "timeText": "原始时间表达",
      "suggestion": "是否需要提醒，以及建议的提醒方式",
      "refId": "创建提醒后返回的任务ID或闹钟标识，未创建时为空字符串"
    },
    "source": "openclaw",
    "notes": "不确定性或补充说明"
  }
}
```

字段说明：

- `query`：用户原始表达，尽量保留原话。
- `content`：真正需要长期记住、后续可查询的内容。
- `imagePaths`：图片路径数组，优先保存复制到固定目录后的路径。
- `imageDescription`：保存时由上层 agent 生成的图片描述。
- `tags`：简短标签，用于帮助后续理解和筛选。
- `reminder`：当备忘含有明确日期、时间、期限、还款日、出行日等时效信息时，记录是否建议提醒以及原始时间表达。`refId` 在用户确认提醒并创建成功后写入，用于后续取消提醒。
- `notes`：信息不完整、用户要求先保存等情况下的补充说明。

## 保存文本备忘

1. 判断用户是否明确要求保存信息，例如“记一下”“备忘”“帮我保存一下”。
2. 提取真正要记住的内容，写入 `content`。
3. 将用户原始请求写入 `query`。
4. 如果内容清晰，使用 `type: "text"`。
5. 能明显提取标签时，写入简短 `tags`。
6. 如果内容包含明确日期、时间、期限或容易错过的事项，写入 `reminder`；用户未确认提醒时使用 `needed: false` 并写入提醒建议。
7. 调用 `scripts/memo_store.py save` 写入备忘。
8. 保存成功后，简短告诉用户已保存，并复述关键信息。

## 保存文本加图片备忘

1. 判断用户是否要保存图片相关信息，例如“保存这张图”“记一下这张发票”“这张截图后面要用”。
2. 获取用户提供的本地图片路径或附件路径。
3. 如果图片路径可用，先调用 `scripts/memo_store.py copy-image` 复制到固定图片目录。
4. 上层 agent 在保存时根据图片内容生成简短 `imageDescription`。
5. 将复制后的图片路径写入 `imagePaths`。
6. 将用户备注或要记住的内容写入 `content`，原始请求写入 `query`。
7. 如果图文备忘包含明确日期、时间、期限或容易错过的事项，写入 `reminder`；用户未确认提醒时使用 `needed: false` 并写入提醒建议。
8. 如果图片无法复制，但原路径仍有价值，可以保存原路径，并提醒路径可能不稳定。

## 信息不完整时先澄清

不要把模糊请求直接写入备忘录。如果保存后的记录很难被未来查询到，应先追问。

需要澄清的例子：

- “帮我记一下这个”，但当前上下文里“这个”不明确。
- “这个后面有用”，但没有说明用途或要点。
- “记一下这张图”，但图片内容复杂，或用户没有说明后续想查什么。

追问要具体，避免开放式泛问。可以问：

- “这条备忘主要用于什么：报销、购物、联系人、待办，还是其他？”
- “这张图需要重点记住哪个信息：金额、位置、物品，还是整张图内容？”
- “你希望之后用什么关键词能查到它？”

用户补充后，将原始请求、补充说明、图片路径和图片描述合并成一条完整 memo 再保存。

如果用户明确说“不用补充，先保存”，则按现有信息保存，并把不确定性写入 `notes`。

## 时效性备忘和提醒建议

保存备忘时，如果内容包含明确日期、时间、期限或容易错过的事项，应主动判断是否需要提醒。例如：

- “5月13号信用卡还款”
- “明天下午 3 点交材料”
- “周五出行”
- “月底前缴费”
- “下周三带体检报告”

### 保存阶段

1. 先正常保存备忘，不要因为提醒信息未确认而放弃保存。
2. 在 memo 中写入 `reminder` 字段，`needed: false`，保留原始时间表达和提醒建议。

### 询问是否设置提醒

保存后，根据用户表达分两种情况：

- **用户未提及提醒**：主动追问，例如：”这条有明确日期，要不要我提前提醒你？”
- **用户已明确说”提醒我””到时候叫我”等**：跳过询问，直接进入下一步。

用户拒绝时，只保留备忘，不创建提醒。

### 确认提醒时间

用户同意提醒后，询问具体时间（如果用户已说明则跳过）：

> “几点提醒你比较好？当天早上、提前一天，还是提前几小时？”

### 创建提醒

确认提醒时间后，按以下步骤执行：

1. **判断来源渠道**：读取 memo 的 `source` 字段，默认在同一渠道推送提醒消息（通过上层 agent 的 cron 或消息推送能力）。
2. **判断是否有闹钟能力**：检查当前加载的 skills 中是否有能设置设备端闹钟的能力（如 `xiaodu-control-official` 的闹钟功能）。如果有，在完成渠道提醒后，额外询问用户：
   > “要不要同时在小度上设个闹钟，到时候直接喊你？”
   用户同意则通过对应 skill 创建设备闹钟。
3. **回写 memo**：将创建成功的提醒任务 ID 或闹钟标识写入 `reminder.refId`，同时将 `reminder.needed` 更新为 `true`。
4. 告知用户提醒已创建，包括渠道和时间。

> **渠道选择原则**：不主动询问用户用哪个渠道，用来源渠道作为默认，设备闹钟作为可选补充。只有当来源渠道无推送能力（如 CLI）时，才主动询问用户偏好。

### 取消提醒

如果用户要取消某条备忘的提醒，读取该 memo 的 `reminder.refId`，通过对应能力取消任务，并将 `reminder.needed` 更新为 `false`，清空 `refId`。

## 查询备忘

只有当用户在查询“已保存备忘内容”时才使用本流程。典型触发表达包括：

- “查一下我之前记的出行日期”
- “备忘录里有没有发票”
- “我记录过身份证放哪了吗”
- “你帮我记过小王喜欢喝什么吗”
- 当前对话上下文明确指向刚刚保存过的备忘

不要因为普通“查一下”触发本 skill。以下请求不属于 AI 备忘录查询：

- “查一下今天天气”
- “查一下路线”
- “查一下新闻”
- “查一下某个公共信息”

这些请求应由上层 agent 使用其他工具或能力处理。

查询步骤：

1. 调用 `scripts/memo_store.py list` 读取备忘记录；备忘较多或只需要近期内容时，可使用 `scripts/memo_store.py list --limit N` 减少输出。
2. 上层 agent 阅读结构化 JSON 后做语义判断，不限制为关键词匹配。
3. 判断相关性时综合 `query`、`content`、`imageDescription`、`tags`、`createdAt`、`updatedAt` 和 `notes`。
4. 返回最相关的结果，包含时间、内容摘要；如果有图片，附上 `imagePaths`。
5. 如果用户请求有歧义，先简短确认：“你是想查已保存的备忘，还是查实时/外部信息？”
6. 如果没有找到相关备忘，明确说明没有找到，并提示用户补充更多线索。

## 隐私和安全边界

- 只读写固定 AI 备忘录目录；当用户要求保存图文备忘时，默认允许复制当前消息或上下文中提供的图片到固定图片目录。
- 不要主动把备忘内容发送到外部服务。
- 不要读取无关私人文件来补充备忘查询结果。
- 将备忘内容视为个人隐私数据。
- 如果 `memos.json` 损坏，不要覆盖原文件；使用脚本备份行为，并告知用户需要修复备忘存储。
